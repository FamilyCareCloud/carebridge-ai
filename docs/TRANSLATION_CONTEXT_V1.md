# 확장 평가 오류 개선: 원문 단서와 의미 범위

이전 [확장 평가](TRANSLATION_IMPROVEMENT_V3.md)의 생성 실패 2건, 주요 의미 오류 5건, 정상 기준문 보류 오탐 1건을 대상으로 개선했다. 기존 원문·기준문·원시 평가 파일은 변경하지 않는다.

## 구현 방식

1. **원문에 있는 단서만 제공한다.** 저녁 식사·휠체어·이동·정원 표현, 걷기 이후/반복 조건, 잠들기 전 숫자 간격, 목말라 보인다는 표현을 실제로 찾은 경우에만 `source_hints`를 해당 구간에 붙인다. 인도네시아어 부정 인용은 한국어 지침을 사용하고, 경험 전체의 부정에는 해당 의미의 지침을 사용한다. 문장 ID나 정답을 조회하지 않고 번역 후 문자열도 바꾸지 않는다. 단서가 없는 요청은 이전과 같은 생성 지침·입력을 유지한다.
2. **의미 범위의 모순을 양방향 검사한다.** 명시된 '걸은 후'를 조건/반복인 '걷다 보면'으로 바꾸거나, 단순 부정을 '한 적이 없다'로 확대하면 모델이 통과시켜도 보류한다. 반대로 명시적인 반복 관찰을 한 번의 사후 관찰로 줄이거나, 경험 부정을 단순한 부정으로 축소한 경우도 보류한다. 실제 반복 조건과 '한 번도' 같은 경험 부정의 다른 표현은 별도로 다룬다. 제한된 표현을 다루는 보조 규칙이며 일반 의미 증명은 아니다.
3. **번역의 불확실성과 발언의 진위 확인을 구분한다.** 모든 구간이 명시적인 직접 인용문 또는 지원하는 반복 보행 관찰이고 대조 접속사가 없는 요청에 한해 짧은 문맥 QA 지침을 적용한다. 나머지 요청은 기존 일반 QA 지침을 유지한다. `uncertainty_preserved`는 '아마/것 같다' 등의 표현 보존을 검사하며, 외부에서 발언의 진위를 확인했는지를 평가하지 않는다. 모델의 실패 판정을 규칙으로 강제 통과시키지는 않는다.

4. **정상 어형과 추가 확인 표시를 보완한다.** '목말라 보였다/목이 말라 보였다'의 불확실성을 인식한다. 단순히 '물이 보였다' 또는 '탈수 증상이 보였다'는 이 규칙으로 추측 표현이 되지 않는다. 모델이 확인 표시를 누락해도 원문에 알려진 불확실성 표지가 있으면 고정된 추가 확인 항목을 만든다. 기존 모델 확인 표시는 제거하지 않는다.

5. **관찰을 의사 표현으로 바꾸지 않도록 검사한다.** 명시적 의사·미래 표지가 없는 부정 발언을 '않겠다고/않겠습니다'로 바꾸면 `SEMANTIC_ADDED_FACTS`로 보류한다. 인도네시아어 부정 인용에는 실제 일치한 부정 동사·대상·오늘 표현의 뜻풀이도 제공한다.

HTTP와 로컬 CUDA 경로는 같은 입력 생성 함수를 사용한다. 단서는 구간별 최대 8개로 제한하고 원문은 자르거나 덮어쓰지 않는다. 모든 번역·관찰의 근거는 계속 원래 원문의 구간이다. 사용자/API 응답에 새 입력 필드를 요구하지 않으며 `carebridge.v1`, `carebridge.workflow.v1`, `carebridge.qa.v2`의 응답 구조·검사 코드도 유지한다.

`pipeline.translation_prompt_sha256`은 이제 시스템 지침뿐 아니라 단서 지침과 정규식·용어·단위·개수 한도 정의를 함께 반영한 지문이다. `semantic_prompt_sha256`도 일반/인용문 지침과 선택 조건을 함께 반영한다. 요청별 최종 프롬프트 문자열의 해시는 아니다. 실제 단서는 고정된 규칙으로 재구성하며 비교 평가에는 실제 모델 입력도 남긴다. 원문/생성본 해시는 기존 정의를 유지한다.

외국어가 남은 미완성 번역, 모델 시간초과, 출력 절단을 성공으로 바꾸지 않는다. 자동 재시도, 다른 모델로의 전송, 사람 검토·공유 제한 해제는 추가하지 않았다.

## 평가 범위

[고정 자료 v3](../evaluation/translation-corpus-v3.json)는 기존 54개 번역을 그대로 유지하고 15개 새 사례를 추가한다. 새 사례는 다른 상태의 걷기 이후 관찰, 실제 반복 조건, 실제 경험 전체 부정, 다른 숫자·식사 종류의 지연, 다른 목적지의 휠체어 이동을 다룬다. 이 원문과 기준문은 첫 단서 GPU 비교 전에 고정했다.

[고정 자료 v4](../evaluation/translation-corpus-v4.json)는 69건을 그대로 유지하고 수프·외출의 부정 인용 6건을 추가한다. 이 6건은 프롬프트 탐색 후, GPU v6 실행 전에 고정한 전이 확인 사례다. [고정 자료 v5](../evaluation/translation-corpus-v5.json)는 이를 유지하고 관찰→미래 의사 변경 QA 3건을 v7 실행 전에 추가한다. 최종 범위는 생성 75건, QA 102건(정상 기준문 48건, 의도적 오류 54건), 편집·음성 등 업무 흐름 26건이다.

반복 개선에 사용하는 개발용 합성 자료이며 원어민 검증·독립 미공개 평가가 아니다. API 성공, 모델의 자체 QA, 코딩 AI의 원문 대조 검토는 서로 구분한다. 실제 사람 검토와 서비스 승인 정책은 별도다.

최종 코드의 자동 테스트는 280건이며 Ruff 검사와 형식 검사를 함께 사용한다. 실제 GPU 검사는 고정된 Qwen3 8B 4bit 스냅샷과 Whisper/LoRA를 사용한다. 평가 스크립트는 출력 파일을 덮어쓰지 않고 실행 코드·자료·모델 지문을 기록한다.

## 최종 검증 결과

2026-10-29, RTX 5070 Ti 16GB에서 실행했다. [전체 GPU v7](../evaluation/spec-gpu-v7.json)의 코드 기준은 `47848a8`, [마지막 의미 QA 재검증](../evaluation/spec-context-qa-v1.json)은 `75539c8`이다.

| 항목 | 결과 |
|---|---|
| 생성 응답·원문 근거·공유 제한 | 75/75 응답, 근거 보존 및 외부 공유 제한 유지 |
| 이전 확장 사례의 실패 | 생성 실패 2건과 주요 의미 오류 5건이 재발하지 않음 |
| 의도적 오역 QA | 54/54 보류 |
| 정상 기준문 QA, 전체 v7 | 47/48 검토 필요, 반복 관찰문 오탐 1건 |
| 오탐 수정 후 영향 범위 GPU 재검증 | 실제 생성본 3건 + 정상 기준문 3건 + 반복 누락 변조 3건 + 기존 부정 대조 3건, 총 12/12 기대 상태 |
| 수정·충돌·실제 음성·장애 흐름 | 26/26 통과 |
| 백엔드 #8 계약 | 전체 응답 200/200 호환; 마지막 실제 생성본/의미 검사 응답 15/15 호환 |
| 전체 번역 지연 | 중앙값 5.067초, 최대 9.888초. 생성과 의미 QA를 포함한 요청 시간 |

v7 전체 실행의 종료 코드는 **1**이다. 정상 반복 관찰문을 기존 일반 의미 모델이 잘못 보류했기 때문이다. 이후 번역 생성 지문을 유지하면서 해당 의미 검사만 변경했고, 원본 보고서 해시·바뀐 앱 파일·영향 사례를 확인한 별도 재검증은 **12/12, 종료 코드 0**이다. 원본 전체 결과를 덮어쓰거나 마지막 코드로 전체 75+102+26건을 다시 실행한 것처럼 합치지 않았다. 정상 기준문 오탐 수정의 근거는 영향 범위 재검증이다.

[원문 대조 기록](../evaluation/spec-reference-review-v7.json)은 코딩 AI의 별도 검토다. 75건 중 주요 의미 오류는 발견하지 못했으며, 15건에는 비표준 활용·중복 표현·정밀도 등 경미한 소견이 남는다. 생성된 베트남어 부정문 1건은 어색한 활용과 함께 의미 QA에서 보류된다. 추가 확인 표시의 과잉 9건, 분류 기준과의 불일치 8건도 별도 기록했다. 이 결과는 독립적인 번역 정확도나 원어민 검증이 아니다.

[전체 백엔드 계약 결과](../evaluation/backend-contract-spec-v7.json)는 backend `a073e7e`의 검증기로 확인했다. 최종 의미 검사 응답은 [추가 계약 결과](../evaluation/backend-contract-spec-context-v2.json)에 기록한다. 추가 계약 v1은 QA 요청용 합성 입력 9건까지 서비스 출력 Draft로 검사해 거절한 범위 오류였다. v2는 실제 생성본 3건과 의미 검사 응답 12건만 검증한다. v1 파일도 보존했다. API 계약 검사는 의미 정확도 검사가 아니다.

원래 GPU 서비스의 설정과 프로세스를 복구했다. 이번 개선 코드는 PR에서 검토하며 공개 서비스 병합·배포는 수행하지 않았다.

GPU 서비스를 확인해 중복 모델 로드를 피하고, 평가 종료 시 기존 프로세스와 설정을 복구한다. 새 출력 파일명을 사용한다.

```powershell
python scripts/compare_translation_prompts_gpu.py --baseline-ref 6ef3409 --candidate-only --corpus evaluation/translation-corpus-v5.json --output evaluation/새로운-단서비교.json
python scripts/evaluate_spec_gpu.py --corpus evaluation/translation-corpus-v5.json --output evaluation/새로운-전체평가.json --audio evaluation/spec-synthetic-english.wav --adapter-path C:/별도준비/whisper-senior-lora
node scripts/check_backend_contract.mjs evaluation/새로운-전체평가.json ../carebridge-backend evaluation/새로운-계약검증.json evaluation/translation-corpus-v5.json
python scripts/recheck_context_audit_gpu.py --parent evaluation/spec-gpu-v7.json --corpus evaluation/translation-corpus-v5.json --output evaluation/새로운-문맥QA.json
```
