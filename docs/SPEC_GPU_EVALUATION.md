## GPU 실행으로 찾아 수정한 문제

1. `지원을 받으며`를 도움 누락으로 판단하던 오탐을 보완했다. 같은 실제 번역이 재실행에서 검토 단계로 돌아왔다.
2. 30분 **동안** 잔 것을 30분 **후**에 잤다고 바꾼 번역을 숫자만 같다고 통과시키지 않도록 했다.
3. 걷기·수프·발언 출처의 명시적 표지가 빠지면 모델의 통과 판정을 보류로 낮춘다. 첫 실행의 발언 출처 오역 1건 및 추가 대상 누락 사례가 최종 실행에서 보류됐다.
4. Whisper의 기본 출력은 종료 토큰을 제거한다. 이를 잘린 전사로 오인하던 구현을 원시 생성 결과/종료 토큰을 확인하도록 수정했다. 실제 영어 전사가 최종 실행에서 성공했다.
5. 실제 생성 시간 0.001초 제한은 504, 출력 128토큰 제한은 502로 반환했다. 부분 결과를 성공으로 제공하지 않았다.

이 보완은 알려진 제한된 표현을 다루는 규칙이다. 모든 행동·대상·언어·지속시간·발언 주체를 검증하는 일반적인 의미 추론기가 아니다.

## 남은 번역 문제

| 사례 | 실제 문제 | 최종 처리 |
|---|---|---|
| en-multiline | 확정 식사를 “먹은 것 같습니다”로 바꾸어 불확실성 추가 | hold |
| vi-uncertainty | 점심을 “오후 식사”로 바꿈 | hold |
| vi-ambiguity | 피곤함을 “어색한 기색”으로 바꿈 | hold |
| vi-chronology | 수면 지속시간을 지연 시점으로 바꿈 | hold |
| id-assistance | 도움·목적지는 남았으나 걷기 행동 누락 | hold |
| id-uncertainty | 한국어가 완성되지 않고 외국어가 남음 | 502 생성 실패 |

비교용 평가의 전체 종료 코드는 **1**이다. 생성 36건이 모두 성공해야 한다는 엄격한 조건에서 마지막 1건이 실패했기 때문이다. 26개 업무 흐름이 통과했다는 이유로 전체 번역 평가 성공이라고 보고하지 않는다. 번역 프롬프트/가중치는 이번 두 실행 사이에 바꾸지 않았고, 오류를 숨기지 않고 드러내는 검사와 STT 처리를 보완했다.

## 음성 검증 범위

Windows Microsoft Zira Desktop으로 합성한 영어 1건:

`Drank water this morning. Walked with help.`

실제 전사문은 기준문과 같았고 1.654초 걸렸다. requires_transcript_review=true를 확인했고, 확인한 텍스트를 reviewed_transcript로 보내 생성하는 흐름도 실행했다. 실제 사용자 확인 화면 조작은 이 오프라인 검증에 포함되지 않는다. 이후 한국어 문장에 “걷었습니다”라는 어색한 활용이 있어 표현 검토는 필요하다. 현장 소음·다른 언어·고령자 음성 품질을 검증한 결과가 아니다.

## 후속 연결

백엔드/프론트는 새 생성 원본 저장, 현재 원문 개정 공급, 사람 편집본 구분, 최종본과 QA의 같은 버전 저장, 독립 제출 중복 방지를 연결해야 한다. 실정보 허용(D01), 사람 확정 제한/재검사 시점(D10), 출시 언어(D12)는 팀 정책이다. 이 변경은 AI 작업 브랜치/PR 상태이며 병합·배포·새 기관 서비스 종단 UI 검증은 별도다.

재현 명령은 [계약 문서](SPEC_WORKFLOW_V1.md#gpu-재현)를 따른다. 백엔드 호환성은 다음처럼 별도 DB/서비스 변경 없이 검사한다.

```powershell
node scripts/check_backend_contract.mjs evaluation/spec-gpu-v2.json ../carebridge-backend evaluation/backend-check-new.json
```
