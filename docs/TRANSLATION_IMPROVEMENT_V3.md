# 번역 생성 품질 개선과 GPU 비교

기존 기능명세 API 구현은 [SPEC_WORKFLOW_V1.md](SPEC_WORKFLOW_V1.md), 이전 GPU 평가와 남아 있던 오류는 [SPEC_GPU_EVALUATION.md](SPEC_GPU_EVALUATION.md)를 참고한다.

## 변경 내용

번역 프롬프트를 원문 보존 원칙과 짧은 한국어 번역 예시 중심으로 정리했다. 완료/추측, 수면 지속시간/잠들기 전 간격, 걷기/도움, 인용문 속 부정을 구분한다. 베트남어·인도네시아어의 일부 용어와 시제 표지를 안내한다. 예시는 전체 평가 문장의 정답 조회표가 아니며 입력에 없는 예시 사실을 삽입하지 않도록 명시했다. HTTP와 로컬 GPU 번역이 동일한 지침을 사용하며 API 응답 스키마는 유지한다.

한국어로만 작성한 첫 후보는 일부 기존 오류를 줄였으나 다른 음식·시제 오류를 만들었다. [첫 비교 출력](../evaluation/prompt-comparison-v1.json)을 보관했다. 긴 용어 안내를 덧붙인 두 번째 후보도 [전체 평가](../evaluation/spec-gpu-v3.json)에서 생성 실패·새 의미 오류를 보여 채택하지 않았다. 세 번째 후보의 [54개 생성 출력](../evaluation/prompt-comparison-v2.json)과 전체 API 평가를 별도로 보존한다. 결과 문자열을 고쳐 쓰거나 실패를 성공으로 바꾸는 후처리, 자동 재시도, 외부 모델 전송은 추가하지 않았다.

검사도 보완했다. 명시된 수면 시작 전 간격이 지속시간으로 바뀌는 반대 방향 오류를 `NUMERIC_FACTS_PRESERVED`로 보류한다. 외출이 화장실 이용 등 다른 행동으로 바뀌면 명시적 원문 표지 검사가 보류한다. 정상 한국어 활용형 '걸은'/'걸을'을 걷기 누락으로 오인하던 부분을 수정했다. 직접 인용과 간접 인용의 형식 차이를 불확실성 변화로 판단하지 않도록 의미 QA 지침을 명확히 했다. 사실·부정·발언 출처는 계속 보존해야 한다.

이 규칙은 제한된 언어·표현만 검사한다. 시간 관계 전체나 모든 행동을 이해하는 검증기가 아니며 자동 검사를 통과해도 사람 검토가 필요하다.

## 기존 오류의 변경 전후

이전 [v2 평가](../evaluation/spec-gpu-v2.json)의 번역 36건은 1건 생성 실패, 5건 의미 오류 보류였다. 새 지침의 동일 36건은 모두 한국어 응답을 생성했다. 아래 6개 문제의 핵심 의미가 개선됐지만, 나머지 표현·문법·확인 표시까지 완벽하다는 뜻은 아니다.

| 사례 | 이전 문제 | 새 번역의 핵심 표현 |
|---|---|---|
| en-multiline | 확정 식사에 '것 같습니다' 추가 | '점심 반 정도 먹었습니다'로 완료 표현 유지. '정도'의 정밀도 문제는 별도 기록 |
| vi-uncertainty | 점심을 오후 식사로 변경 | '점심 식사 후에 잤을 수도 있습니다' |
| vi-ambiguity | 피곤함을 어색한 기색으로 변경 | '피곤해 보입니다. 이유는 분명하지 않습니다' |
| vi-chronology | 30분 수면을 30분 후 수면으로 변경 | '점심 후 30분 동안 잤고 오후 3시에 깨어났습니다' |
| id-assistance | 걷기 누락 | '도움을 받아 화장실로 걸었습니다' |
| id-uncertainty | 미완성 한국어와 외국어 혼합 | '점심 식사 후에 잠을 잤을 수도 있습니다' |

한국어 표현과 분류·확인 표시도 별도 검토한다. 예를 들어 '마셨지 않았습니다', '반량', '반 정도'는 교정/정밀도 확인이 필요하고, 원문이 확정적이어도 확인 질문 표시를 켜는 사례가 있다. 자동 성공률을 일반 번역 정확도로 표시하지 않는다.

## 최종 실측 결과

평가 코드 `b5d3196`, 2026-10-29 01:37:01–01:44:48 KST. RTX 5070 Ti의 Qwen3 8B 4bit와 Whisper 실가중치를 사용했다. 모델 스냅샷과 패키지·코드·자료·프롬프트 해시는 [전체 API 실행](../evaluation/spec-gpu-v4.json)에 기록했다. 로딩 11.874초, 최대 PyTorch 할당 8,491.7MiB/예약 8,680.0MiB이며 전체 VRAM 사용량과는 다르다.

| 검증 항목 | 결과 | 의미 |
|---|---:|---|
| 자동 회귀 검사 | 229 통과 | 코드·스키마·오류 처리 |
| 기존 36건 생성 | 36/36 응답, 보류 0 | 원문 대조에서 major 0, minor 4. 일반 정확도 아님 |
| 확장 포함 생성 | 52/54 응답, 보류 4 | 새 사례의 실패 2건을 포함 |
| 원문 근거·공유 차단 | 52/52 | 반환된 초안의 구조 계약 |
| 의도적 오역 QA | 33/33 보류 | 기존 27건 + 시간 관계 반전 6건 |
| 정상 기준문 QA | 26/27 검토 필요 | 인도네시아어 인용문 1건 보류 오탐 |
| GPU 업무 흐름 | 26/26 | 사람 편집·재생성·충돌·실제 시간초과/절단·음성 |
| 실제 응답→백엔드 계약 | 135/135 | Draft 65 + Review 70, 실패 요청 2건 제외 |
| 생성+QA 지연 | 중앙값 5.066초 / 최대 8.903초 | 응답 성공 52건 기준 |

백엔드는 `a073e7ee23d0991fa2373287d6da164257703cb8`의 검증기로 검사했다. [계약 검증 기록](../evaluation/backend-contract-spec-v4.json)은 응답 형식·근거·집계 호환성만 확인하며 번역 의미의 정확도를 확인하는 검사가 아니다.

합성 영어 음성은 `Drank water this morning. Walked with help.`로 전사됐다(1.687초). 미리 정한 전사 기준문을 사람이 확인한 입력으로 가정해 생성한 초안은 '오늘 아침 물을 마셨습니다. 도움을 받아 걸었습니다.'였다(5.143초). 음성 1건의 제한된 검사이며 실제 사람의 확인 화면이나 다양한 언어·잡음 성능을 검증한 것은 아니다.

## 남은 문제와 적용 범위

[원문 대비 별도 AI 검토](../evaluation/spec-reference-review-v4.json)의 분류는 전체 clean 36, minor 11, major 5, unavailable 2다. 기존 36건은 clean 32/minor 4, 새 18건은 clean 4/minor 7/major 5/unavailable 2다. 코딩 AI가 기준문과 대조한 기록이며 원어민 평가가 아니다.

- 새 사례의 생성 실패 2건: 영어 미확인 저녁 식사, 인도네시아어 휠체어 이동. 외국어가 남은 결과를 502로 거절했다.
- 새 의미 오류 5건 중 **2건만 자동 보류**됐다. 베트남어·인도네시아어의 잠들기 전 20분 간격을 20분 수면으로 바꾼 오류는 새 검사가 잡았다.
- **3건은 자동 QA가 놓쳤다.** 영어·인도네시아어의 '걸은 후'를 '걷다 보면'으로 바꾼 경우와 인도네시아어 발언의 단순 미섭취를 '마신 적이 없다'는 경험 전체 부정으로 넓힌 경우다. 의도적 오역 대조군 33/33을 이 생성 오류까지 검증했다는 뜻으로 해석하면 안 된다.
- 생성문 중 minor 2건도 보류됐다(베트남어 산책/걷기 표현과 비표준 부정 활용). 별도의 정상 기준문 QA에서는 `id-extension-quoted-negation-faithful`을 불확실성 변화로 오인했다.
- 기준과 다른 확인 질문 표시가 6건 있었다. 세 언어의 원문 분류는 이번 기준 범위와 일치했다. 문법·표현·수량 정밀도·질문 과잉 표시의 개선과 원어민 검토가 계속 필요하다.

**전체 평가 종료 코드는 1**이다. 생성 실패 2건과 정상 기준문 보류 오탐 1건이 남아 엄격한 성공 조건을 만족하지 못했다. 업무 흐름 26/26이나 기존 36건 개선을 근거로 서비스 번역 품질이 완성됐다고 판단하지 않는다.

평가 후 원래 GPU 서비스의 번역 모델·STT 로딩을 확인해 복구했다. 이번 변경은 PR의 코드/증거 갱신이며 공개 서비스 병합·배포는 수행하지 않았다. 사람 검토·공유 차단은 유지되며 신규 명세 API의 백엔드·프론트 연결은 별도 작업이다.

## 평가 설계와 재현

- 기존 36개 개발 회귀 사례를 그대로 유지했다.
- 첫 후보의 출력 확인 전에 새 합성 사례 18개와 기준 번역을 고정했다. 세 언어별로 지속시간/지연, 미확인 완료, 피곤함, 걷기 부정과 휠체어·도움, 인용된 부정을 다룬다.
- [확장 자료](../evaluation/translation-corpus-v2.json)는 번역 54건, QA 60건(정상 27건, 의도적 오역 33건)이다. 기존 자료의 해시도 기록했다.
- 최종 지침은 신규 API를 통하여 실제 CUDA 생성과 의미 QA, 기존 편집·충돌·시간초과·출력 절단·합성 영어 음성 경로를 함께 평가한다.
- 평가기는 자료의 실제 사례 수를 사용한다. 백엔드 계약 검증기는 평가 자료의 해시와 ID를 확인하므로 다른 자료로 만든 평가를 섞어 검증할 수 없다.
- 사례와 기준은 코딩 AI가 작성한 개발용 자료다. 반복 실험으로 지침을 선택했으므로 독립 평가/원어민 평가/현장 정확도라고 해석하지 않는다. HTTP 성공, 모델 자기 검사, 원문 대조 AI 검토는 서로 구분한다.

기존 GPU 프로세스의 신원을 확인해 중지하고, 테스트가 종료되면 원래 서비스와 설정으로 복구해야 한다. 외부 서비스를 시작하지 않는 오프라인 평가 명령은 다음과 같다.

```powershell
python scripts/compare_translation_prompts_gpu.py --baseline-ref f3aa4f8 --output evaluation/새로운-지침비교.json
python scripts/evaluate_spec_gpu.py --corpus evaluation/translation-corpus-v2.json --output evaluation/새로운-전체평가.json --audio evaluation/spec-synthetic-english.wav --adapter-path C:/별도준비/whisper-senior-lora
node scripts/check_backend_contract.mjs evaluation/새로운-전체평가.json ../carebridge-backend evaluation/새로운-계약검증.json evaluation/translation-corpus-v2.json
```

기존 파일을 덮어쓰지 않는다. 첫 명령의 candidate는 실행 당시 체크아웃의 프롬프트이므로 첫 비교를 재현하려면 기록된 후보 지침을 확인해야 한다. 합성 음성 및 로컬 모델 가중치는 별도 준비한다.
