# CareBridge QA v2: 이관 후 사실 보존 검사

저장소: FamilyCareCloud/carebridge-ai. 구현 기준은 main이다.
이름이 바뀐 저장소의 기존 모델·전사·검토 API 위에 아래 검사를 추가했다.

## 보완 사항

- 영어 `with help/assistance`, 베트남어 `với sự hỗ trợ`, 인도네시아어 `dengan bantuan`
  등 명시적인 도움 표현이 한국어에서 빠지면 ASSISTANCE_FACT_PRESERVED로 보류한다.
  임의 언어의 모든 사실 누락을 검출하는 검사가 아니다.
- 모델 재검사에 no_omitted_facts를 필수 불리언으로 추가했다.
  도움·행동·대상·시점·완료 여부·발언 출처 누락을 SEMANTIC_OMITTED_FACTS로 검사한다.
  누락 필드/잘못된 형식은 검사 성공으로 처리하지 않는다.
- 숫자는 시각을 분리해 비교한다. 15:00↔오후 3시, 14:30↔14시 30분,
  00:05↔오전 12시 5분처럼 명확히 같은 시각은 허용한다.
  오전/오후 반전, 시각 누락·중복, 함께 적힌 수량 변경은 보류한다.
  단독 `3시`처럼 오전/오후가 불명확한 표현을 15:00으로 추정하지 않는다.
  일반적인 시간대·기간·단위 변환을 수행하는 기능은 아니다.
  명시된 UTC/GMT/KST와 오프셋의 변경·누락도 보류하며 시간대를 임의 변환하지 않는다.
- 알려진 피곤함의 외관 표현, unknown/모름 등의 제한된 어휘 신호를 보완했다.
- 번역 프롬프트는 문장 완결성·행동·도움·대상·발언 출처·수면 분류 보존을 명시한다.

원문, 해시, 인용 위치는 정규화하지 않는다. 비교용 표현만 처리한다.
사람 검토 필수·공식기록 아님·자동 공유 금지 계약을 유지한다.

## 함께 적용할 백엔드

carebridge-backend develop용 보완은 구간별 근거·필수 검사·집계 일치를 확인하며,
새 필수 검사 없이 승인된 과거 버전은 재검사·재승인을 요구한다.
프론트는 기존 API·상태·QA 항목 목록을 계속 사용한다.

적용 순서:

1. AI를 먼저 배포/재시작하고 /health의 carebridge_qa_revision=carebridge.qa.v2를 확인한다.
2. AI의 기존 키·모델 캐시·Whisper 어댑터는 배포 환경에서 준비한다. Git에는 넣지 않는다.
3. 백엔드 변경을 적용한다. 새 백엔드를 구 AI와 연결하면 검사가 실패하며 승인되지 않는다.
4. 기존 승인본에 새 검사 항목이 없다면 검토자가 재검사 후 다시 승인한다.

백엔드의 이전 계약은 추가 QA 코드를 허용하므로 AI를 먼저 올릴 수 있다.
검사 형식을 바꾸는 배포이므로 두 PR을 독립적으로 자동 배포하지 않는다.

## 검증 범위

테스트는 이전 합성 평가에서 빠졌던 도움 정보 3개 언어, 동등/변경/누락/중복 시각,
일반 숫자 보존과 필수 의미 검사 필드를 확인한다. 모델 응답은 테스트 대역이다.
새 프롬프트의 실제 GPU 번역 정확도나 원어민 품질이 입증됐다는 뜻은 아니다.
기존 36건 평가 수치를 수정 후 성적으로 재사용하지 않는다.

재현: `python -m pytest -q`, `ruff check app tests scripts`,
`ruff format --check app tests scripts`.

2026-10-28 검증: AI 테스트 149건, 백엔드 테스트 67건 통과.
실제 FastAPI의 정상·보류 응답을 Node 검증기에 넣은 계약 호환성 2건도 통과했다.
이 호환성 확인 역시 모델 추론은 대역을 사용했다.
